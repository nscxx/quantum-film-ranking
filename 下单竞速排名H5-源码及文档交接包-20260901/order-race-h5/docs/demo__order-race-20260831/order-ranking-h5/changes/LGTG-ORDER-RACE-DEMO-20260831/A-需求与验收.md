# 下单竞速排名H5演示版｜需求与验收

## 1. 背景与问题

- 原始需求与背景：活动现场需要一个横向大屏，将每个人的下单数量以竞速排名的方式实时展示；另有一个独立录入页，由工作人员选择人员并手动输入订单号。
- 要解决的业务问题：现场观众无法直观看出谁领先、谁刚刚完成新订单；工作人员也缺少一个简单、可追查且不会把同一订单重复计算的录入入口。
- 参考方向：借鉴用户提供的小红书“竞速答题”中横向进度条和实时排名的表达，制作更深色、更霓虹、更有科技感的原创页面，不照搬其页面。

### 4.4 场景覆盖结论

- 正向：覆盖大屏查看、订单录入、单个新增和批量导入。
- 逆向/异常/失败：覆盖空值、过长字段、接口失败和错误提示。
- 重复/重试/权限：覆盖订单全场去重；权限作为演示边界外风险，明日优先确认。
- 并发/乱序/历史兼容：覆盖数据库唯一约束与刷新后恢复；首次新建无旧数据兼容。
- 页面职责：覆盖大屏纯展示和录入页独立访问；大屏不提供跳转到录入控制台的入口。
